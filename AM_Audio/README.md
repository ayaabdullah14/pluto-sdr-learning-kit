# Example 05: AM audio transmission with two ADALM-PLUTO devices

Builds on the AM sine-wave link (`AM_Mod_Demod/pluto`). Same chain, but the message is audio.

## Status (read first)
- Calculated and checked in Python: audio level, TX peak amplitude, bandwidth, power split (`results/tx_level_check.txt`).
- Tested only on synthetic data: `scripts/compare_audio.py` recovered a known delay (12345 samples), gain (0.37) and note frequencies from a fake recording (`results/compare_audio_SYNTHETIC_selftest.txt`).

## 1. Purpose and project connection
You learn to carry a real, changing signal (audio) through an SDR link, to convert sample rates between the sound card, GNU Radio and the Pluto, and to measure how well the recovered message matches the original (delay, shape, frequency, SNR). In the project, the same rate-conversion and comparison skills apply to a beacon signal and to logged measurements.

## 2. Requirements
- 2 Pluto devices, 2 laptops (Windows 11, Radioconda), `iio_info` working on both.
- Wired chain `TX -> 30 dB attenuator (+20 dB) -> SMA cable -> RX` (recommended first), or antennas 1 to 2 m apart.
- Headphones on Laptop 2 (avoid acoustic feedback; demodulated noise can be loud).
- Python with numpy, scipy (and optionally matplotlib) for `compare_audio.py`.
- Put `test_audio_48k.wav` in the same folder as `am_audio_tx_pluto.grc` (a copy is in `flowgraphs/`). If GNU Radio cannot find it, set the variable `wav_path` to the full path.

## 3. New concepts
| Term | Meaning |
|---|---|
| Audio band | Frequencies a person hears; speech is mostly below 4 kHz |
| Rational Resampler | Block that changes sample rate by Interpolation/Decimation (`up/down` ratio) with an anti-alias filter |
| Interpolation | Raising the sample rate by inserting samples and filtering |
| Decimation | Lowering the rate by filtering and dropping samples |
| Occupied bandwidth | Width the signal really takes: 2 x highest audio frequency for AM |
| Cross-correlation | Slides one signal over another to find the delay where they match best |
| Underrun / overrun | The sound card or Pluto runs out of or overflows with samples (prints `aU`, `O`, `U`) |

## 4. Signal path
### TX (Laptop 1)
| Block | In -> Out | Type | Rate | What it does |
|---|---|---|---|---|
| Wav File Source | none -> audio | float | 48 kS/s | Plays `test_audio_48k.wav`, repeat on |
| Low Pass Filter | audio -> audio | float | 48 kS/s | Cuts above 4 kHz (transition 1 kHz) |
| Multiply Const (`m`) | audio -> m*audio | float | 48 kS/s | Sets modulation depth |
| Rational Resampler | float -> float | float | 48 kS/s -> 960 kS/s | Interpolation 20, Decimation 1 |
| Add Const (1) | -> 1 + m*audio | float | 960 kS/s | Envelope |
| Multiply Const (`carrier_amp`) | -> scaled envelope | float | 960 kS/s | Amplitude 0.4 |
| Float To Complex | float -> complex | complex | 960 kS/s | Q = 0 |
| Multiply with Signal Source (carrier, +100 kHz) | -> AM | complex | 960 kS/s | Modulator |
| PlutoSDR Sink | complex -> RF | complex | 960 kS/s | Radiates at `lo_freq` + 100 kHz, applies `tx_atten` |
No Throttle: the Pluto sets the pace. Optional: Audio Source (microphone) replaces the wav (disabled by default).

### RX (Laptop 2)
| Block | In -> Out | Type | Rate | What it does |
|---|---|---|---|---|
| PlutoSDR Source | RF -> I/Q | complex | 960 kS/s | Manual gain `rx_gain` |
| Frequency Xlating FIR Filter | -> baseband | complex | 960 kS/s -> 96 kS/s | Center Frequency `fc_rx` -> 0 Hz, +-15 kHz, Decimation 10 |
| Complex to Mag | -> envelope | float | 96 kS/s | Envelope detector |
| DC Blocker | -> no constant | float | 96 kS/s | Removes the carrier level |
| Low Pass Filter | -> audio band | float | 96 kS/s | 4 kHz cutoff |
| Rational Resampler | -> audio | float | 96 -> 48 kS/s | Interpolation 1, Decimation 2 |
| Multiply Const (`volume`) | -> scaled | float | 48 kS/s | Manual volume |
| Audio Sink | -> speaker | float | 48 kS/s | Plays through headphones |
| File Sink (disabled) | -> file | float | 48 kS/s | Raw float32 `recovered_audio.f32` for analysis |

Sample-rate chain: 48k x20 = 960k (Pluto) ; 960k / 10 = 96k ; 96k / 2 = 48k (sound card). Every sink and filter uses the rate at its own point.

## 5. Configuration table
| Parameter | Value | Why | Effect of changing |
|---|---|---|---|
| `samp_rate` | 960000 | 48000 x 20, lighter than 2.4 MS/s | Must keep the integer chain; change both laptops |
| `lo_freq` | 2450000000 | Same on both | Different values: no reception |
| `fc` (TX) | 100000 Hz | Away from the DC spike | Equal to the RX peak position |
| `fc_rx` (RX) | 100000, tune with slider | Clock offset moves the carrier | Wrong value shifts audio pitch or loses it if beyond 15 kHz |
| Low Pass Filter (TX) Cutoff Freq | 4000 Hz | Limits bandwidth to 8 kHz | Higher: wider signal; lower: dull sound |
| `m` | 0.6 | Audio peak is 0.9, so peak modulation is 0.54: no overmodulation | Up to 1 still safe; audio peaks are not sine peaks |
| `carrier_amp` | 0.4 | Peak 0.4 x 1.54 = 0.62 (calculated) | Keep peak below 1 |
| `tx_atten` | 40 dB | Safe start | Lower = stronger |
| `rx_gain` | 30 dB | Starting point | Too high = clipping |
| `volume` | 1 | Start low | Recovered level is arbitrary |
| Xlating cutoff / transition | 15 kHz / 5 kHz | Tolerates carrier error and covers +-4 kHz audio | Narrower may cut the signal |

## 6. Step by step
1. Wired chain connected. Both Plutos recognized (`iio_info -s`).
2. Laptop 2: open `am_audio_rx_pluto.grc`, Execute. Volume low, headphones on.
3. Laptop 1: open `am_audio_tx_pluto.grc`, `tx_atten` = 40, `m` = 0.6, Execute.
4. RX tab 2: find the carrier near +100 kHz. Move `Carrier position` to its peak.
5. RX tab 3: carrier at 0 Hz with sidebands within +-4 kHz. Tab 4: recovered audio and spectrum.
6. Raise `volume` slowly until you hear the melody, sweep and chord.
7. Verification recording: enable the File Sink block, run 25 s, stop. Then on a computer with Python:
   `python scripts/compare_audio.py assets/test_audio_48k.wav recovered_audio.f32`
8. Fill the worksheet.

## 7. Expected results
- TX tab 2 (audio spectrum): peaks at 440, 554, 659, 880 Hz during the melody; a moving peak during the sweep (300 to 3500 Hz); peaks at 500 and 1500 Hz during the chord. Nothing above about 4 kHz.
- TX tab 3 and RX tab 2: carrier at +100 kHz, audio sidebands from about 96 to 104 kHz (8 kHz wide). Sidebands move constantly with the audio.
- Carrier carries most of the power: with this audio (mean square 0.302) and m = 0.6, only 9.8 percent of the power is in the sidebands (calculated).
- RX carrier is not exactly at 100 kHz (clock offset of tens of kHz is possible).
- Audio you hear: the same melody, with hiss. Pitch is correct only if `fc_rx` equals the true carrier position (not needed for envelope detection, but a carrier far off can partly leave the filter).
- `compare_audio.py` (hardware): high correlation, delay about hundreds of ms (USB, buffers, sound card), note frequencies within 2 Hz, SNR depends on your signal level. I did not measure these.

## 8. Verification (success criteria)
1. No flat tops in raw I/Q (tab 1).
2. Recovered note frequencies within 5 Hz of the original (from `compare_audio.py` or the audio spectrum in tab 4 with a 4096 FFT, bin 11.7 Hz).
3. Correlation coefficient above 0.9.
4. Sweep is heard as a smooth rising pitch without breaks.
5. Increasing `tx_atten` by 10 dB lowers the carrier peak by about 10 dB on the RX but does not change the pitch of the notes.

## 9. Guided experiments (one change at a time)
1. Set `m` to 0.2, 0.6, 1.0. Predict the sideband level change and loudness before observing.
2. Set the TX Low Pass Filter cutoff to 1500 Hz. What happens to the sweep and the chord?
3. Move `fc_rx` 10 kHz from the carrier. What changes in tab 3? In the sound?
4. Raise `tx_atten` in 10 dB steps until the audio is lost. Record the level where it becomes unintelligible.
5. Raise `rx_gain` until I/Q clips. What does it sound like?
6. Replace the wav with the microphone (headphones on the TX laptop to avoid feedback).

## 10. Troubleshooting
| Symptom | Possible causes | Check | Correction |
|---|---|---|---|
| Red block | Version differences | Error text | Send it to me |
| `Wav File Source` cannot open | Wrong path | Console message | Use a full path in `wav_path` |
| Silence at RX | TX not running, `lo_freq` differs, too weak | Tab 2 peak | Match, lower `tx_atten` |
| Hum or buzz | Carrier outside filter, overmodulation | Tab 3, `m` | Tune `fc_rx`, lower `m` |
| Loud hiss | Low SNR | Carrier vs floor in tab 2 | Raise signal, lower distance |
| Distorted loud parts | Clipping or `m` too high | Tab 1 I/Q; TX peak | Lower `rx_gain` or `m` |
| Printed `aU` or `O` | Sound card vs Pluto clock mismatch, CPU | Console | Close programs, USB 2.0 port directly, lower `samp_rate` to 480000 and adapt ratios |
| Pitch wrong | Sample-rate mismatch after Resampler | All rates in the table | Fix |
| Audio only at the start then fades | DC Blocker/AGC effects or carrier drift | Tab 2 | Retune `fc_rx` |

## 11. Understanding check
1. Why filter the audio to 4 kHz before modulating?
2. What is the occupied bandwidth if the audio goes to 4 kHz?
3. Why is the TX Rational Resampler Interpolation 20, and the RX Decimation 10 then 2?
4. Why can't you tell the delay from a pure tone?
5. Why might the recovered amplitude not match the original?
6. Why is most of the power in the carrier?

Answers (after trying): 1) to keep the signal narrow and avoid interfering outside 8 kHz; 2) 2 x 4 kHz = 8 kHz; 3) 48k x 20 = 960k, 960k / 10 / 2 = 48k; 4) a tone repeats, so many delays look alike; 5) gains, path loss and the filter scale the level; 6) the carrier is the "1" in `1 + m*audio`, the sideband power is `m^2 * <x^2>` compared with 1 for the carrier, so for m = 0.6 and mean square 0.302 the sidebands are only 0.109 of the carrier power (9.8 percent of the total).
