# تجربة: استقبال إشارة معروفة وقياس قدرتها (Relative Digital Power)

الملفات: `flowgraphs/tx_tone_atten.grc` و `flowgraphs/rx_tone_power.grc` (وبجانب كل واحد ملف Python المولَّد منه: `tx_tone_atten.py` و `rx_tone_power.py`).

## 0. ما الذي تم التحقق منه فعلاً (اقرأ هذا أولاً)

| الحالة | المعنى | ما تم |
|---|---|---|
| **حساب (Calculation)** | معادلات على الورق | القدرة، التوسط الخطي، الهبوط المتوقع 10 dB، تأثير الضجيج |
| **محاكاة عددية (Numerical simulation)** | Python/numpy فقط | `scripts/averaging_order_check.py` |
| **تنفيذ برمجي فعلي (Software execution)** | GNU Radio حقيقي بدون Pluto | الملفان `.grc` تُرجما بنجاح باستخدام `grcc` (إصدار GNU Radio 3.10.12.0)، وتم **تشغيل سلسلة القياس نفسها** (نفس الـ blocks ونفس الإعدادات) مع إشارة ونَوْز مولَّدين بالبرنامج بدل الـ Pluto (`scripts/gnuradio_headless_test.py`، النتائج في `results/`) |
| **اختبار العتاد (Hardware test)** | Pluto حقيقي | **لم يتم.** كل نتائج العتاد فارغة في ورقة النتائج لتملأها أنت |

ملاحظة: التجميع تم على Python 3.12.16، وأنت تستخدم 3.12.9 (نفس الفرع 3.12، ولا يُتوقع فرق).

## 1. هدف التجربة
أن تتعلم ثلاثة أشياء:
1. كيف تعرف أن الإشارة التي تراها في الـ spectrum هي إشارتك أنت (بتشغيل/إيقاف المرسل).
2. كيف تقيس قوتها كرقم واحد ثابت (متوسط القدرة في قناة ضيقة).
3. كيف تتأكد أن القياس يستجيب بشكل صحيح لتغيير معروف: زيادة TX attenuation بمقدار 10 dB يجب أن تُنزل قراءة الإشارة نحو 10 dB.

علاقتها بمشروعك: كل Anchor سيقيس قدرة إشارة Beacon الروبوت. إذا لم يستجب القياس بشكل منطقي لتغيير معروف، فلا يمكن الوثوق به في الـ EKF.

## 2. المتطلبات
- جهازان Pluto وحاسوبان (Windows 11 Pro)، GNU Radio Companion 3.10.12.0، Python 3.12.
- الهوائيان متصلان، المسافة بينهما 1 متر أو أكثر، ويبقيان ثابتين طوال التجربة.
- عمل `iio_info -s` على كل حاسوب (انظر الفقرة 4).

## 3. مفاهيم جديدة (بلغة بسيطة)
| المصطلح | معناه |
|---|---|
| **Relative digital power** | قدرة محسوبة من أرقام الـ I/Q داخل GNU Radio. هي ليست dBm |
| **P = mean(I² + Q²)** | القدرة = متوسط (مربع I + مربع Q) لكل العينات |
| **Linear average** | نحسب المتوسط على القيم الخطية أولاً، ثم نحوّله إلى dB |
| **المرجع (0 dB)** | عينة قيمتها `|z|² = 1` في تيار `PlutoSDR Source`. لذلك القيم عادةً سالبة (مثل -50 dB) |
| **Baseline** | القراءة والمرسل متوقف. هي قدرة الضجيج داخل القناة |
| **TX attenuation** | تقليل قدرة المرسل بالـ dB. **رقم أكبر = إشارة أضعف** |
| **Frequency offset** | الساعتان في الجهازين مختلفتان قليلاً، فيظهر الحامل في مكان غير الذي ضبطتَه (بضعة kHz) |
| **Selected channel** | القناة الضيقة التي يقيس فيها الفلتر (هنا ±5 kHz حول مركز الفلتر) |

## 4. كيف تجد الـ URI لكل حاسوب
1. وصّل الـ Pluto بمنفذ **USB** (وليس PWR). افتح **Radioconda Prompt**.
2. نفّذ: `iio_info -s`
3. ستظهر أسطر مثل (الأمثلة تقريبية، ستختلف عندك):
```
Available contexts:
    0: 0456:b673 (Analog Devices Inc. PlutoSDR (ADALM-PLUTO)), serial=104400... [usb:1.5.5]
```
4. انسخ النص الذي بين `[` و `]` (مثلاً `usb:1.5.5`). إذا كان لديك عنوان شبكة يعمل فقد تستخدم `ip:192.168.2.1`.
5. في كل ملف `.grc` افتح المتغير `pluto_uri` واكتب النص بين علامتي اقتباس: `"usb:1.5.5"`.
6. **عندك حاسوبان:** كل حاسوب له URI الخاص بجهازه. قد يكون الاثنان متشابهين لأن كل جهاز موصول بحاسوب مختلف.
7. إن كانت لديك إعدادات تعمل (مثل `samp_rate` أو `lo_freq`)، ضعها في المتغيرات أعلى اللوحة بدل القيم الافتراضية. **المهم أن تتطابق `lo_freq` في الجهازين.**

لا تستخدم `lo_freq` ممنوعاً في بلدك. إن لم تكن متأكداً، استخدم **السلك مع attenuators** (تجربة سلكية) بدل الهواء.

## 5. شرح الدوائر (من اليسار إلى اليمين)

### المرسل `tx_tone_atten`
```
Signal Source (complex tone) ──► PlutoSDR Sink
```
| Block | الدخل → الخرج | الإعدادات المهمة |
|---|---|---|
| Signal Source | لا شيء → complex | Waveform = Cosine، Frequency = `tone_offset` (100000 Hz)، Amplitude = `tone_amp` (0.5)، Sample Rate = `samp_rate` |
| PlutoSDR Sink | complex → إشارة راديو | Attenuation = `tx_atten`، LO = `lo_freq`، Sample Rate = `samp_rate`، URI = `pluto_uri` |
- نغمة معقدة: `0.5·exp(j2π·100000·t)`. التردد الحقيقي في الهواء = `lo_freq + 100000` Hz.
- لا يوجد Throttle: الـ Pluto يتحكم في السرعة.
- المتحكم الوحيد: شريط `TX attenuation (dB)` (يبدأ عند 30).

### المستقبِل `rx_tone_power`
```
PlutoSDR Source ──┬─► QT GUI Frequency Sink              (شاشة 1: أين النغمة؟)
                  └─► Frequency Xlating FIR Filter ─► Complex to Mag^2 ─► Moving Average ─► Nlog10 ─► QT GUI Number Sink   (الرقم)
```
| Block | الدخل → الخرج | النوع | معدل العينات | وظيفته |
|---|---|---|---|---|
| PlutoSDR Source | راديو → I/Q | complex | 960000 | Gain Mode = Manual، Gain = `rx_gain` (30 dB، ثابت) |
| QT GUI Frequency Sink | complex → شاشة | complex | 960000 | يعرض الطيف بالتردد النسبي (Hz)؛ النغمة قرب +100 kHz |
| Frequency Xlating FIR Filter | complex → complex | complex | 960000 ← 48000 | Center Frequency = `fc_rx`، Decimation = 20، Taps = `firdes.low_pass(1, samp_rate, 5e3, 2e3)` |
| Complex to Mag^2 | complex → float | float | 48000 | I² + Q² لكل عينة |
| Moving Average | float → float | float | 48000 | Length = 48000 (ثانية واحدة)، Scale = 1/48000 → المتوسط الخطي |
| Nlog10 | float → float | float | 48000 | n = 10، k = 0 → 10·log10(P) |
| QT GUI Number Sink | float → رقم | float | | يعرض الرقم النهائي بالـ dB |

لماذا الفلتر مهم: يحذف كل ما حول النغمة، فيصبح الرقم قدرة النغمة + ضجيج ±5 kHz فقط، وليس ضجيج 960 kHz كلها.

**ملاحظة صادقة:** في الإصدار 3.10.12.0 لا يمرّر block `PlutoSDR Source` الإعداد Bandwidth إلى الجهاز (فحصتُ الكود المولَّد)، لذلك حذفته من المستقبِل. الـ filter يُختار تلقائياً (`Auto`).

## 6. خطوات التشغيل الدقيقة

### أ. الإعداد
1. افتح **Radioconda Prompt** على كل حاسوب.
2. انتقل إلى مجلد الملفات، مثلاً: `cd C:\path\to\flowgraphs`
3. اضبط `pluto_uri` (و `lo_freq` و `samp_rate` إن لزم) في الملفين.
4. تشغيل بطريقتين:
   - من GRC: `gnuradio-companion` ثم افتح الملف ثم زر Execute، أو
   - من الـ Prompt: `python tx_tone_atten.py` على الحاسوب 1 و `python rx_tone_power.py` على الحاسوب 2 (إذا أعدت التوليد من GRC فالملفات تُحدَّث).

### ب. التجربة المضبوطة (لا تحرّك الهوائيات ولا تغيّر `rx_gain` ولا `lo_freq` ولا `samp_rate`)
1. **Baseline:** شغّل المستقبِل والمرسل **متوقف**. انتظر 3 إلى 5 ثوانٍ حتى يستقر الرقم. سجّل القراءة `P_off`. انظر الـ spectrum: لا توجد نغمة واضحة.
2. **التعرّف على الإشارة:** شغّل المرسل (`tx_atten` = 30). يجب أن يظهر قمة جديدة في الـ spectrum وترتفع القراءة. أوقف المرسل: تختفي القمة وتعود القراءة إلى `P_off`. أعد تشغيله. **هذا الاختبار (تشغيل/إيقاف) هو الذي يثبت أن القمة إشارتك وليست تداخلاً.**
3. **تحديد الحامل الحقيقي:** في الـ spectrum افتح Control Panel (القائمة اليمنى) وفعّل Peak Hold و Marker وضع العلامة على القمة. اقرأ ترددها `f_peak` (قد يكون 100.0 إلى 100.x kHz أو أبعد). ثم اضبط الشريط `Measurement filter centre (Hz)` ليساوي `f_peak` بدقة ±100 Hz.
   - **الإزاحة** = `f_peak − 100000`. إن كانت كبيرة (مثلاً +20 kHz) فهذا فرق الساعتين وهو طبيعي.
   - **قاعدة مهمة:** يجب أن تكون القمة داخل ±3 kHz من مركز الفلتر. في المحاكاة، عند 4.2 kHz بدأ الفلتر يضعف القراءة، وعند 6.7 kHz ضاعت الإشارة تماماً (انظر الفقرة 7).
4. **القراءة الأولى:** انتظر 3 إلى 5 ثوانٍ ثم سجّل `P_30` (مع `tx_atten` = 30). سجّل أيضاً مدى تذبذب الرقم.
5. **تغيير 10 dB:** حرّك الشريط إلى `tx_atten` = 40 فقط (لا شيء آخر). انتظر 3 إلى 5 ثوانٍ. سجّل `P_40`. احسب `P_40 − P_30`.
6. **الرجوع:** أعد `tx_atten` إلى 30. انتظر. سجّل `P_30'`. احسب `P_30' − P_30`.

اختيار نقطة البداية: إن كانت النغمة في الخطوة 2 أعلى من الـ baseline بأقل من 15 dB، فالقياس سيكون ضعيفاً: قرّب الهوائيين قليلاً (ثم ثبّتهما) أو قلّل `tx_atten` للبداية (مثل 20 ثم 30). لا تبدأ أبداً من 0 dB، ولا ترفع `rx_gain` بعد البدء.

## 7. ما المتوقع
**الهبوط المتوقع عند زيادة التوهين 10 dB:** مساهمة الإشارة تنزل 10 dB. لكن الرقم الذي تقرؤه يشمل الضجيج أيضاً، لذلك الهبوط الكلي أقل من 10 dB عندما تكون الإشارة قريبة من الضجيج. نتائج التشغيل البرمجي الفعلي لسلسلة GNU Radio (إشارة ونَوْز مولَّدان):

| SNR في القناة عند 30 dB | هبوط القراءة عند 40 dB | الهبوط حسب المعادلة | خطأ الرجوع إلى 30 |
|---|---|---|---|
| 40 dB | -10.00 dB | -10.00 dB | 0.00 dB |
| 20 dB | -9.64 dB | -9.63 dB | 0.00 dB |
| 10 dB | -7.42 dB | -7.40 dB | 0.01 dB |
| 0 dB | -2.60 dB | -2.60 dB | 0.01 dB |

كيف تقدّر SNR عندك: `ON − OFF` بالـ dB = `10·log10(1 + Ps/Pn)`. مثال: إذا كان الفرق 20.04 dB فإن `Ps/Pn ≈ 100` أي SNR ≈ 20 dB.

أشياء أخرى في المحاكاة: الضجيج وحده بدون إشارة أعطى -54.08 dB (المتوقع -54.07 dB)، وتذبذب الرقم نحو 0.03 dB فقط. **في العتاد سيكون التذبذب أكبر.** لا تتوقع نفس القيم المطلقة، فالمرجع نفسه (ربح الـ RX) يعتمد على جهازك.

**أثر خطأ التمركز (من التشغيل البرمجي، إشارة قوية):**
| إزاحة النغمة عن مركز الفلتر | القراءة |
|---|---|
| +0.3 kHz | -14.06 dB |
| -2.7 kHz | -14.04 dB |
| -4.2 kHz | -14.83 dB (بدأ التأثير) |
| -6.7 kHz | -53.84 dB (ضاعت الإشارة) |
| -11.7 kHz | -54.05 dB (ضجيج فقط) |

## 8. معايير النجاح (يجب أن تتحقق كلها)
1. القمة تظهر وتختفي مع تشغيل/إيقاف المرسل، وترتفع القراءة وتنخفض معها.
2. القراءة تستقر خلال 5 ثوانٍ (التذبذب أقل من حوالي 1 dB؛ إن كان أكبر فاكتب السبب).
3. `P_40 − P_30` قريب من -10 dB إذا كان SNR كبيراً، أو قريب من القيمة المحسوبة من الجدول/المعادلة بحسب SNR الذي قدّرته (ضمن ±1.5 dB).
4. `P_30' − P_30` ضمن ±1 dB.
5. لم تظهر أشكال مقصوصة في الـ spectrum (لا توجد قمم متعددة غريبة) ولم تغيّر `rx_gain`.

## 9. تجارب موجَّهة
1. غيّر `tx_atten` من 30 إلى 20 ثم 30 ثم 50. توقّع القراءة قبل أن تنظر إليها.
2. حرّك مركز الفلتر 5 kHz بعيداً عن القمة. ماذا يحدث للرقم؟ ولماذا؟
3. أوقف المرسل أثناء القياس وراقب أبطأ وقت يستغرقه الرقم ليعود إلى الـ baseline (يجب نحو ثانية).
4. (اختياري) مرّر يدك قرب الهوائي وراقب. هذا يريك سبب الحاجة إلى EKF لاحقاً.

## 11. أسئلة للفهم
1. لماذا نحسب المتوسط قبل تحويله إلى dB؟
2. هل القراءة -50 dB تعني -50 dBm؟
3. إذا زدت `tx_atten` 10 dB وانخفضت القراءة 3 dB فقط، فما التفسير؟
4. لماذا يجب أن يكون مركز الفلتر قريباً من القمة؟
5. لماذا لا نغيّر `rx_gain` بين القياسين؟

**الإجابات (بعد أن تحاول):** 1) لأن متوسط قيم dB ينحرف: في المحاكاة العددية أعطى -2.512 dB لضجيج قدرته الحقيقية 0 dB. 2) لا، فهي نسبة إلى مرجع رقمي داخلي بدون معايرة. 3) الضجيج أو التداخل يشكّل جزءاً كبيراً من القدرة الكلية، فينقص جزء الإشارة فقط. 4) لأن الفلتر لا يمرّر ما بعد ±5 kHz تقريباً. 5) لأن تغيير الربح يغيّر القراءة بنفس القدر، فلن تعرف أيّ تغيير سببه TX.

## 13. شرط الانتهاء
تستطيع: تحديد إشارتك بتشغيل/إيقاف المرسل، إيجاد الحامل الحقيقي وتوسيط الفلتر عليه، قراءة القدرة النسبية، التنبؤ بالتغيّر عند تغيير TX attenuation بما فيه تأثير الضجيج، والقول بوضوح إن القياس **نسبي وغير معاير**.
